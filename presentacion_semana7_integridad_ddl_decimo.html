Tema de la semana

Restricciones de integridad

Cuando una sentencia rompe una regla, el motor la rechaza con un error. Ese error no es una falla: es la base de datos protegiéndose.

📓 Para el cuaderno

Mapa de los tipos de integridad

Unicidad

No hay filas ni valores repetidos donde no debe haberlos.

PRIMARY KEYUNIQUE

Error típico: 1062

Dominio

Cada columna solo acepta valores válidos.

tipo · NOT NULLDEFAULT · CHECK

Errores típicos: 3819, 1048, 1364

Referencial

Cada clave foránea apunta a una fila que existe.

FOREIGN KEYON DELETE / ON UPDATE

Errores típicos: 1452, 1451

ALTER TABLE tabla ADD CONSTRAINT nombre_restriccion tipo (...);
-- uq_... para UNIQUE · chk_... para CHECK · fk_... para FOREIGN KEY
Ponle nombre a cada restricción: el mensaje de error te dirá cuál regla se rompió y podrás borrarla o cambiarla por su nombre.

Una FK no se edita: se borra y se crea de nuevo

  
Cambiar la regla de una clave foránea

  

  

    

      
1 · Averiguar su nombre. Las FK de PulsoFit se crearon sin nombre; MySQL les puso uno automático.

      
SHOW CREATE TABLE asistencias;

      
Resultado (columna Create Table)
CONSTRAINT `asistencias_ibfk_1` FOREIGN KEY (`socio_id`) REFERENCES `socios` (`id`)

      
En Workbench: clic derecho sobre la celda → Open Value in Viewer.

    

    

      
2 · Borrar la FK por su nombre.

      
ALTER TABLE asistencias DROP FOREIGN KEY asistencias_ibfk_1;

      
Output
✓ 0 row(s) affected

    

    

      
3 · Crearla de nuevo con nombre y con la regla deseada.

      
ALTER TABLE asistencias
  ADD CONSTRAINT fk_asistencias_socio
  FOREIGN KEY (socio_id) REFERENCES socios(id)
  ON DELETE CASCADE
  ON UPDATE CASCADE;

      
Output
✓ 15 row(s) affected

    

    

      
4 · Probar. Una socia sin membresías, con 2 asistencias, se borra: sus asistencias se borran solas.

      
SELECT COUNT(*) FROM asistencias WHERE socio_id = 13;   -- 2
DELETE FROM socios WHERE id = 13;
SELECT COUNT(*) FROM asistencias WHERE socio_id = 13;   -- 0

      
CASCADE es poderoso y peligroso: un solo DELETE puede borrar muchas filas de otras tablas.

Sentencias que cambian la estructura de tablas e índices. Practicamos sobre una copia para no dañar el gimnasio.







  
📓 Para el cuaderno

  
Tablas, columnas e índices

ALTER TABLE planes_copia ADD COLUMN descripcion VARCHAR(50) DEFAULT 'Sin descripción';
ALTER TABLE planes_copia RENAME COLUMN descripcion TO detalle;
ALTER TABLE planes_copia MODIFY detalle VARCHAR(80);

CREATE INDEX idx_planes_copia_precio ON planes_copia (precio);

CódigoIntegridadCómo se corrige normalmente

1452Referencial (hijo sin padre)Usar una FK que exista en la tabla padre

    
1451Referencial (padre con hijos)Tratar primero los hijos o cambiar ON DELETE si el negocio lo pide

    
1701Referencial (TRUNCATE de un padre)No usar TRUNCATE en tablas padre
